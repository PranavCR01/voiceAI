## M0-2: Utterance manifest schema
**Runs in:** cloud · **Depends on:** M0-1

### Context
Every dataset, augmentation and provider run speaks one format: a JSONL manifest of utterances. Getting this right first prevents every loader inventing its own shape.

### Scope
`harness/datasets/manifest.py`:
- Pydantic v2 model `Utterance`: `utt_id` (stable, deterministic), `dataset`, `subset`, `speaker_id`, `audio_path` (relative to a configurable data root), `channel` (int | None), `start_s`, `end_s` (float | None, for segments within longer files), `ref_text` (verbatim), `sample_rate`, `license`, `synthetic: bool`, `augmentation: list[AugmentStep]` (empty for originals; each step = `kind`, `params`, `seed`), `parent_utt_id` (for augmented copies), `exclude_reason` (str | None).
- `read_manifest(path) -> list[Utterance]`, `write_manifest(path, utts)`; write is sorted by `utt_id` so diffs are stable.
- Validation: `end_s > start_s` when both set; `utt_id` unique within a manifest.

### Acceptance
- [ ] Round-trip test (write → read → equal).
- [ ] Tests for each validation error.
- [ ] `docs/PROJECT.md` or a short `harness/datasets/README.md` documents the schema.

## M1-1: Text normalization and WER
**Runs in:** cloud · **Depends on:** M0-2

### Context
Pooled WER is the headline (see DECISIONS: per-utterance mean overweights short turns). Normalization disputes are the #1 way WER comparisons go wrong.

### Scope
`harness/metrics/normalize.py`, `harness/metrics/wer.py`:
- Wrap Whisper `EnglishTextNormalizer` (pin the package version; record it in results metadata). Strip PriMock57 tags (`<UNSURE>…</UNSURE>` keep inner text, `<UNIN/>` handled per M1-3's exclude rule) *before* normalization.
- `score_utterance(ref, hyp) -> UttScore` with S, D, I, N, hits and the jiwer alignment.
- `pooled_wer(scores)` = Σ(S+D+I)/ΣN; `mean_utt_wer(scores)`.
- Empty reference handling: excluded from per-utterance mean, insertions still counted in pooled (document the choice in DECISIONS).

### Acceptance
- [ ] Fixture table `tests/fixtures/normalization_cases.jsonl` covering: "twenty five" vs "25", "$1,250" vs "1250 dollars", "don't"/"do not", "co-pay"/"copay", "anaesthetic"/"anesthetic", fillers ("um"), casing/punctuation, "10 mg" vs "ten milligrams". Test asserts the *current* normalized output so behavior changes are visible in diffs; cases the normalizer gets "wrong" are documented, not hidden.
- [ ] Pooled vs mean diverge on a fixture with one long and several short utterances.
- [ ] Hand-computed S/D/I on 3 small cases.

## M1-2: Statistics — paired bootstrap, Wilson, Holm
**Runs in:** cloud · **Depends on:** M0-1

### Scope
`harness/metrics/stats.py`, NumPy only, seeded `np.random.Generator`:
- `paired_bootstrap(per_utt_errors: dict[system, arrays of (errors, N)], n=10_000, cluster_ids=None, seed)` → per-system pooled-WER CI and pairwise difference CIs (95% percentile). Resamples utterance IDs (or clusters of them when `cluster_ids` given) identically across systems.
- `wilson_interval(k, n, alpha=0.05)`.
- `holm(pvalues)` → adjusted / reject flags. For bootstrap differences, p-value = two-sided proportion of resamples crossing zero (document).
- `distinguishable(diff_ci) -> bool` (CI excludes 0).

### Acceptance
- [ ] Wilson matches a known reference value (e.g. k=0,n=10; k=5,n=10) to 1e-6.
- [ ] Identical systems → difference CI contains 0 and `distinguishable` is False.
- [ ] Clearly different synthetic systems → distinguishable.
- [ ] Same seed → identical output.
- [ ] Holm matches a hand-worked example.

## M1-3: PriMock57 loader
**Runs in:** cloud (code + fixture tests); actual download runs on owner's machine · **Depends on:** M0-2

### Context
PriMock57 (CC BY 4.0, verified): `github.com/babylonhealth/primock57`, Git LFS. Audio WAV 16-bit/16 kHz, doctor and patient on **separate channels/files**. Transcripts are Praat TextGrid, one interval per utterance (`xmin`, `xmax`, `text`). Tags: `<UNSURE>…</UNSURE>`, `<UNIN/>`. Check the repo's `audio/` and `transcripts/` file naming before coding; don't assume.

### Scope
- `data/fetch_primock57.sh`: clones into `data/raw/primock57` with git-lfs at a pinned commit SHA. Not run in CI.
- `harness/datasets/primock57.py`: parse TextGrid (small hand-written parser or `praatio`, pinned), emit one `Utterance` per non-empty interval with `start_s/end_s`, `speaker_id` = `{consultation}_{doctor|patient}`, `channel`/role recorded, `license="CC-BY-4.0"`.
- Exclude rule: intervals containing `<UNIN/>` get `exclude_reason="unintelligible"` (kept in manifest, skipped in scoring). Intervals shorter than 0.3 s get `exclude_reason="too_short"`. Document both in DECISIONS.
- CLI: `uv run python -m harness.datasets.primock57 --root data/raw/primock57 --out data/manifests/primock57.jsonl`.
- Commit the generated manifest only if it contains no audio and only text already under CC BY 4.0 (it does — add attribution line in `data/manifests/ATTRIBUTION.md`).

### Acceptance
- [ ] Tiny hand-written TextGrid fixture (both speakers, one `<UNSURE>`, one `<UNIN/>`, one empty interval) → expected manifest.
- [ ] `utt_id` deterministic across runs.
- [ ] Script and pinned SHA documented in `docs/RESEARCH.md`.

## M1-5: Medical entity tagging and entity recall
**Runs in:** cloud · **Depends on:** M1-1, M1-2

### Context
This is the project's most persuasive metric. Tagging rules are subjective, so they are published and tested.

### Scope
`harness/metrics/entities.py`, `data/lexicons/medications.txt`:
- Categories: `medication`, `dosage` (number + unit: mg, mcg, ml, units, puffs, tablets), `date` (incl. DOB forms like "third of March nineteen eighty", "03/03/1980"), `number` (phone, IDs, generic digits), `duration` ("for three days").
- Medication lexicon: start from terms observed in PriMock57 transcripts + a public-domain list (openFDA drug names — confirm terms and record source + date in RESEARCH.md). Lowercase, one per line, multi-word allowed.
- Tag spans in the *normalized* reference; after alignment, an entity is recovered iff every reference token in the span is a hit. Per-category recall with Wilson CI.
- Keyterm false insertions: given a boost list, count hypothesis occurrences of boosted terms not aligned to a reference occurrence.
- Separate `formatted_entity_accuracy` on *unnormalized* text for dosage/date/number (does "10 mg" come out usable?).

### Acceptance
- [ ] Fixture sentences with hand-labeled spans per category; tagger output matches.
- [ ] Recall: one substitution inside a multi-token span → that entity is missed.
- [ ] False-insertion count on a fixture where the hyp hallucinates a boosted drug name.
- [ ] Tagging rules written up in `harness/metrics/ENTITIES.md`.
